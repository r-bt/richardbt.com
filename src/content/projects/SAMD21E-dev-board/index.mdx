As a kid I loved my Arduino Uno and always wanted to make my own. After learning Eagle and how to mill PCBs, I made a dev board for the SAMD21E microcontroller, with a micro USB, barrel jack, reset button and status LEDs.

![Labelled dev board](./dev-board-labelled.png)
*Labelled dev board*

## Designing a dev board

I built it in spirals. First I implemented everything in Prof. Neil Gershenfeld's HTMAA example [schematic](http://academy.cba.mit.edu/classes/embedded_programming/index.html) for a SAMD21E board, then added the extras.

### Breaking out the pins

I wanted to break out all the pins for future breakout boards. I used horizontal pins instead of vertical ones so the board wouldn't stab me if I put it in my pocket. I broke out every unused pin on the SAMD21E except four:
- **PA00** and **PA01** are oscillator pins meant for a crystal. I didn't need one, so I ignored them
- **PA27** and **PA28** I kept for on-board status LEDs

I connected them to FTDI headers. There were more header pins than SAMD21E pins, so I added ground and 5V / 3.3V pins in some places. My first ordering wasn't the best, but I rearranged things during routing and it all worked out.

![Header schematic](./header-schematic.png)
*Header schematic*

### Adding a reset button

With Arduino code, sometimes things go wrong, you end up in a weird state, or you just need to start over. Most Arduino boards have a reset button for this, and I wanted one too.

The microcontroller restarts whenever the reset pin is brought to ground. The pin is already used by the JTAG, so I connected my extra components to the same net: the pin goes through a 100ohm resistor to 3.3V, and a button shorts the line to ground when pressed.

![Button schematic](./button-schematic.png)
*Button schematic*

### Power and status LEDs

I wanted one LED that's always on when the board has power, plus two more for debugging and status. The power LED is wired directly to 3.3V and ground.

![Power LED schematic](./power-led-schematic.png)
*Power LED schematic*

For the status LEDs, I wired resistors and LEDs to **PA27** and **PA28**.

### Micro USB

Of course I wanted to be able to program the board, so I included a micro USB.

![Micro USB schematic](./micro-usb-schematic.png)
*Micro USB schematic*

### Barrel jack connector

I won't always have my computer around, so I wanted to power the board from a barrel jack. That supplies 12V, so I added a 5V regulator, which connects to the same 5V line as the micro USB.

The barrel jack has a switch. When on, it sends the regulator's 5V to the board and to a pin. When off, the 5V only goes to the pin.

## Routing the board

I'll admit I was a little scared to route this one. My previous boards had far fewer components. I started by placing the SAMD21E in the centre and connecting it to the FTDI headers. Routes were going to cross, so instead of adding 0 ohm resistors I swapped pins around in the schematic until nothing crossed.

Then I placed and routed everything else. In the end I needed no vias or 0 ohm resistors. The trick was running a ground trace along the far side of the FTDI header pads and routing underneath the SAMD21E and the button.

### Adding a little flair

The only thing left was a bit of flair.

In my freshman year, the number 1213 came up while I was writing equations on a whiteboard. My handwriting is atrocious, so the digits mashed together into something that looked like RB, which conveniently are my initials. Ever since, I've put 1213t on things I make. Not just any 1213t, though: it's written in an obscure font I found during Metropolis' water jet training. I've never found the font again, so I have to dig up a saved copy whenever I want it.

![1213t initials](./initals.png)
*My initials*

I had them saved as an SVG, but Eagle has incredibly poor support for images. I followed a [SparkFun guide](https://learn.sparkfun.com/tutorials/importing-custom-images-into-eagle), which has you install a ULP script for SVGs. On a Mac, you can find the ULP folder under **your profile (top right)** > **Preferences** > **Electronics** > **Directory** > **Directory for ULP**.

![ULP directory in Eagle settings](./eagle-ulp-directory.png)
*ULP directory in Eagle settings*

I ran the svg2poly script, picked my file and clicked **Ok**.

![svg2poly prompt](./eagle-svg-2-polygon-prompt.png)
*svg2poly prompt*

Nothing appeared 😥, whatever scale I tried. Next I tried a bitmap: I exported the SVG from Illustrator and imported it with **run import-bmp**. RGB had too many colours, and greyscale showed off how old Eagle is by opening a colour dialog so large I couldn't reach the ok or cancel buttons.

![Colour dialog too large for the screen](./eagle-too-many-colors.png)
*Colour dialog too large for the screen*

Only black-and-white bitmap mode worked, and the result was literally made of individual coloured squares. The warning I'd skimmed said as much: the feature is meant for tracing over with the polygon tool, not for keeping.

![1213t imported as a bitmap](./eagle-bitmap-1213t.png)
*1213t imported as a bitmap*

The last option was DXF. I re-exported from Illustrator and ran **run import-dxf**. The first attempt showed nothing, but after fiddling with the scale something finally appeared.

![1213t imported as a DXF](./eagle-dxf-1213t.png)
*1213t imported as a DXF*

With my clearance settings the traces were too close together, and Eagle wouldn't let me move them directly. I had to deform each letter to satisfy the rules, move it individually and reassemble everything, then fill the letters with **Polygon** > **Polygon Pour from Outline**. It looked pretty awful, and worse in the Othermill.

![Awful CAM plan for 1213t in the Othermill](./awful-1213t-mill.png)
*Awful CAM plan for 1213t in the Othermill*

It no longer looked like my signature. Two hours in and pretty frustrated, I finally did what I should have done at the start and googled it. **The Othermill can engrave SVGs directly.** Why couldn't I have realised that two hours earlier?

### Milling the board

I wanted to try PCB engraving bits instead of the 1/64” bit I'd been using. The 1/64” costs around $18 and breaks easily because it's so small. Engraving bits cost ~$1 and last much longer, since their taper leaves a lot more metal. They're also faster: switching from the 1/64” FEM to a 0.005” engraving bit cut my milling time from 39 to 25 minutes.

I followed a [guide](https://support.bantamtools.com/hc/en-us/articles/115001656913-Engraving-Bit-Isolation-Milling) from Bantam Tools (what Othermill rebranded to) on setting up the engraving bit. I laid the double-sided tape carefully so none of it overlapped, since that would cause a height difference. Then I measured the material and tape with digital callipers and entered it under **thickness**.

Adding the SVG in the Bantam Tools software was super easy, exactly like adding a .brd file: **Open file**, select the SVG, and change the tool to the **0.005” PCB engraving bit**. Then in the **Plan setup** tab I positioned the text where I wanted it engraved.

![Othermill job](./othermill-job.png)
*Othermill job*

The milling job ran and everything worked great.

## Soldering

The SAMD21E is a pretty small chip, so I soldered it with solder paste and a hot air gun, then did the rest of the components by hand.
